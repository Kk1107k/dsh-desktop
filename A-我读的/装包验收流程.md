## 阶段 2 · 首次启动（**核心**，5 项验收）

启动后按时间线核对（预期数字来自 dev 实测）：

| 时刻 | 预期 |
|---|---|
| ~0.8s | splash 出现（鲸鱼 + 品牌字书写动画） |
| ~3.6s | host 就绪 |
| ~3.7s | 主窗口接管 `127.0.0.1:3080` |
| ≥2.4s | splash 最短展示满足后才转场，300ms 淡出 |

**验收清单：**

- [ ] **① 转场**：splash 动画完整播完才消失，**不被腰斩**；无长时间停在"即将就绪…"
- [ ] **② 主窗口**：UI 完整渲染（侧栏 / 新会话 / 工作区 / 输入框 / 模型挂件），**不是白屏也不是 401 页**
- [ ] **③ 托盘**：右下角**黑色鲸鱼**图标；右键菜单**六项**顺序为
      「打开 DSH 桌面 / 检查更新… / 运行模式 / 设置 / ——— / 退出 DSH Desktop」；
      「标准」勾选、其余三项灰色；**徽章应为绿色**（host 健康 = running）
- [ ] **④ 关窗**：点 X → 窗口消失但**进程不退、托盘仍在**；再点托盘「打开 DSH 桌面」→ **窗口能回来**
- [ ] **⑤ 单例**：再次双击快捷方式或 exe → **只唤起已有窗口**，任务管理器不出现第二套进程

**日志核对**（打开 `main.log`）：

- [ ] 有 `spawning host gen=0 port=3080`
- [ ] 有 `host ready line parsed port=3080 token=<redacted>`（token **已遮蔽**，不应出现明文）
- [ ] 有 `转场门控启动` 与至少一行 `gate: hostHealthy=... mainLoaded=... readyToShow=...`
- [ ] **不应出现** `splash finish confirm timeout, force destroy`

## 阶段 3 · 更新链路（装包才有意义）

> dev 态不执行真实更新；`isPackaged=true` 后才会真跑。
> **预期结果**：GitHub 主源（国内不通）→ 降级 COS → COS 域名仍是 `<占位 COS 域名>` → 失败。

- [ ] **自动检查**：主窗口就绪后自动触发一次（**不是立刻**，在转场完成后）
- [ ] **手动检查**：点托盘「检查更新…」
- [ ] 预期看到：**更新窗口打开并显示 error 态**（"无法连接更新服务" + 手动下载入口按钮）
- [ ] 日志里应看到**两次**失败：先 GitHub 实例、再 COS 实例
      （这是 A05「真实转向 COS 实例」的证据 —— 只改 channel 不算降级）

**已知缓修项（不是 bug，别当缺陷报）**：
SPEC §7:251 要求的"**原生**手动下载/关闭对话框 + 固定下载地址"已裁定缓至发布准备期
（需 COS 桶配好才有触发条件）。所以这里预期是**页面内的 error 态**，而不是原生对话框。

**本次验不了的**（如实标注，不算失败）：
- 「已是最新 → 托盘 5s 文字」：两源都失败，拿不到 latest 态
- 「稍后 24h 延后」：拿不到 available 态，snooze 路径无法触发
- 「发现新版本」整条链路：需真实 COS 域名或可达的 GitHub

## 出问题时的快速定位

| 现象 | 先查什么 |
|---|---|
| 装了但打不开 / 一闪而过 | 是否有 dev 实例占着单例锁；`main.log` 最后几行 |
| splash 后白屏 | 主窗口是否 401（cookie 换取失败）；控制台错误 |
| 窗口卡在"即将就绪…" | `main.log` 的 `gate:` 行 —— 哪个条件为 false |
| 托盘无图标 | 图标文件是否随包（`resources/app.asar` 内的 assets）；日志有无 createFromPath 报错 |
| 启动失败弹"服务启动超时" | host 定位外部 node 是否成功；npx 缓存是否还在 |
