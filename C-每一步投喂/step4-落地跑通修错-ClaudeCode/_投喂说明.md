## 两阶段执行（同一终端，不换模型）

### 阶段 A · GLM-5.3 + **high**

修 2 个 P0（`dsh-host.js` 的 `locateRuntime` 桩；三处 ESM 里的 `require`）
→ 补 5 个文件 → `pnpm install` → `pnpm build:preload` → `pnpm typecheck` 修到全绿
→ **commit**，回报 `git log -1 --oneline`

> 阶段 A 先别跑 `dev` / `build`，结束标准：`build/preload.cjs` 能生成、`tsc --noEmit` 无错。

### 阶段 B · 同一终端，等 A 生成完把档位调到 **xhigh**

```bash
pnpm test        # node --test tests/acceptance.test.mjs
pnpm dev         # 应看到 splash → 主窗口接管 3080 → 托盘出现黑色鲸鱼图标
pnpm build       # electron-builder --win nsis --x64 --publish never
```

修错迭代，每修完一处 commit。

## 验收点

- [ ] splash 出现 → 主窗口接管 `127.0.0.1:3080` → **托盘出现黑色鲸鱼图标**
- [ ] 打包产物出现，体积 < 130MB
- [ ] NSIS 装 / 卸 / 启动正常
- [ ] 每修一处 `git commit -m "fix: ..."`

## 💰 省钱的关键（在 CC-Switch 下要重新理解）

"报错 → 改 → 再报错"要跑几十轮。交给国内版积分会烧掉 1000~1600；
交给 Claude Code 走 API 只花几十元。

但**不要为了省那点 API 费用中途换模型** —— 换模型要重开终端，上下文清零后
重新熟悉项目的时间成本，远高于省下的钱。省钱靠的是：同一个终端里把档位调低
（阶段 B 后期可以回落到 **medium**），而不是换模型。

### 卡壳时（同一问题 2 轮没解）才换终端

1. 重开终端，切 **DeepSeek V4.1**，档位 **medium**
2. 新终端第一条消息：**先粘 `接续上下文-换终端用.md` 并填好卡点**，再粘报错
3. 两个模型错误模式不同，交叉验证命中率明显更高
